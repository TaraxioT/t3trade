# P4: one named-beat timeline for the cockpit replica

Status: in progress (this file is updated as work lands, not at the end).

## Plan

1. `src/lib/beats.ts`: ordered beat list with weights; helpers that turn a beat
   name (or a span/slice of beats) into `--from/--to` values. Boundaries are
   chosen so every existing literal range is reproduced exactly (see mapping
   below), so the story timing does not move.
2. Convert all eight replica components + replica.css to derive ranges from
   beats. Generated keyframes (chart draw, status walk, progress arc) are fed
   from the beat list via the existing `<Fragment set:html>` mechanism.
3. `src/lib/beats.test.ts`: ordering invariants (long status >= entry,
   stop mark >= stop-placed >= entry, settled P&L >= target-hit), wired into
   the `build` script chain.
4. Unify desktop/mobile on the one beat map: mobile keeps the same
   `--from/--to` numbers and gains scroller length (padding) instead of a
   second story; the pass window is retuned and verified by scrub.
5. Scrub verification at 1440x900 and 390x844, frames under
   `orchestration/shots/p4/`, read with agy-vision.
