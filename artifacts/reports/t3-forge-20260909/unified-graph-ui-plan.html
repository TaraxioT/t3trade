Verdict: make the chart the work surface

The reveal belongs in the instrument, not at the bottom of the transcript. Make the existing trading thread a two-pane research workspace. The chart occupies roughly two-thirds of the available content width; conversation occupies the rest. Forge is an action and capability inside that workspace, not a separate product tab or dashboard.

This is an independent, bold UI direction. It can be implemented alongside Forge without adopting new trading semantics. It uses the same September 9–11 budget: U0 is F0, U1 is F4, U2 is F6. No extra days and no application redesign beyond this path. All finished data surfaces use real sources; the schematic below contains no market data and is only a layout preview.

Target composition

At 1440×900, collapse the project sidebar to its existing compact mode when the user selects “Focus instrument.” Keep a way back. The remaining content uses minmax(0, 1fr) 360px for instrument and conversation. Inside the instrument, reserve a 240–280px inspector only when opened; otherwise give that width to the chart. At 1920×1080 the conversation can grow to 400px, never steal half the screen. At 1024px the inspector overlays/discloses within the instrument; at 768px stack the panes with a deliberate Chart/Conversation switch and a retained composer. Mobile app implementation remains out of scope.

Top to bottom: one market/source header → range/interval rail → real price/volume plot → aligned detector lane → version/policy evidence footer. The conversation shows compact stage receipts and the next requested action; code opens in a drawer. Do not put a second chart or giant fee card into the chat.

Visual system

Element Concrete specification Reason
Surfaces Existing --background / --card / --border / --primary; flat main canvas, one subtly raised inspector. Radius 8px controls, 12px drawer. No glass layers inside plot. Premium through hierarchy, not nested decorative cards.
Type Existing system sans. 20–24px instrument title, 14px primary data/controls, 12–13px secondary metadata; tabular numerals. Use mono only for hashes/code. Readable at demo distance without changing the product’s identity.
Spacing 8px base rhythm; 16px pane padding; 24px between distinct decision groups; 8px within a group. Minimum 36px pointer controls and visible keyboard focus. Makes relationships consistent and leaves enough room for the actual plot.
Color Existing blue accent for active selection/build action; neutral price comparisons distinguished by stroke/dash and text; amber stale/pending; red failure; green only confirmed success. Color never alone communicates status; avoid six competing pool/regime colors.
Chart Main plot ≥360px tall at 1440×900; detector lane 88–112px; inspector independently scrolls. Price/volume/signal align on one time axis, with explicit gaps for missing readings. The new capability visibly changes an instrument. A gap cannot be mistaken for a zero.
Motion Optional one-time 160ms opacity transition on installed lane, no geometry expansion, no continuous shimmer/pulsing/ticker. Reduced motion removes transition. Installation feels like a result, not a dashboard animation.
Density One visible newest build receipt; older stages in disclosure. Source freshness always visible. Code and query in drawer, never wide-open by default. Judges see causality immediately; engineers can still inspect proof.
Controls Primary action changes with state: Build → Review installation (if needed) → Approve pool → Inspect live policy. Pause stays adjacent to active policy. A single clear next action without hiding independent stop controls.

Exact interaction decisions

  • Build: conversation request starts a real job. Receipt has 4 compact stages and actual elapsed time from server events. Failed test opens the relevant failure; no fake percentage progress. The chart retains its previous data throughout generation.
  • Install: successful authorized installation attaches a named lane automatically, without moving the viewport. Empty output says “Installed · waiting for the next indexed window.” Do not draw a placeholder signal. Clicking the version opens the sealed source/test/manifest drawer.
  • Observe: three pool traces share a normalized % change mode; the y-axis explicitly says normalized change, not ETH spot price. Optional single-pool actual-price view labels quote token. Selecting a pool highlights its contribution and qualifying volume. The signal lane shows regime text plus a subtle categorical band; gaps are gaps.
  • Revise: compare v1/v2 in the same detector lane on the same authentic historical window; show excluded trade count and changed pool eligibility. A pinned “Historical comparison · timestamp” header replaces Live. Return to Live is a clear action. No second competing full chart.
  • Attach: a compact inspector says “Observes Ethereum · controls Sepolia.” Show token pair, pool identity, approved funding bounds, effective fee, installed version, confirmed policy version and expiry. Transaction approval explains what will be created/funded. A wallet balance is not a spending grant.
  • Confirm: keep the currently effective fee visible while showing the proposed change below. Confirmation comes from receipt + state read-back; no optimistic “live” state. A swap evidence row reports actual fee and policy/hash context, distinct from a quote.
  • Stop: direct Pause is persistent whenever policy is enabled. Immediately show local publication paused; separately show on-chain pause pending/confirmed. Revocation/withdrawal live in the same inspector; they are not hidden behind agent conversation.
  • Existing product: Research menu retains legacy study navigation and labels. Hyperliquid trading is a contextual destination with existing order/positions controls. When there is active exposure, a compact persistent position strip includes direct reduce/close access; Forge focus cannot hide risk.
  • Environment: the active environment owns chat, source, capability and pool. Switching it clears displayed previous-environment reads and loads the selected scope, with explicit loading/unavailable states. Do not show the last environment’s data as the new one.
